# 運用モード：読み比べ用（AI経由・集計なし）

各SNSの検索AIに、同じ日に、同じ問いを渡し、返ってきた投稿を並べて読むための文書です。

この文書は単独で使います。共通部分 `core.md` とは結合しません（`tools/build_prompt.py` の対象外です）。共通部分の用語と節を参照する箇所は「共通部分第x節」と書きます。

設計水準は、共通部分第7.4節の水準N（投稿例として語られ方を読むことだけ）です。構成比・区間・SNS間の判定は行いません。それらは日常用・深掘り用（水準P）で行います。

---

## Y1. 目的と、言えること・言えないこと

目的：同じお題について、各SNSの検索AIがどんな投稿を挙げるかを並べ、質感の違い（語られ方、発信者の種別、長さ、画像・動画の有無）を読みます。

| | 内容 |
|---|---|
| 言えること | 「このSNSのAIは、この日、この問いに、これらの投稿を挙げた」。挙げられた投稿の中での種類の内訳。並べて読んだときの違い |
| 言えないこと | SNS全体での割合・順位・多い少ない。「このSNSでは話題になっていない」。利用者の年代・性別・居住地などの属性 |

AIが選んだ投稿は、無作為でも網羅でもありません。結論の主語は、SNSではなく「そのSNSのAIが挙げた投稿」です。

---

## Y2. 設定票

- 運用モード：READING
- run_id：READ-{問いを渡す日YYYYMMDD}-{お題の短い名前}（例：READ-20261116-heartwarming）
- 型：{{READING_TYPE}}（THEME：お題型／CONTRAST：対比型）
- お題：{{THEMES}}（お題型は1つ、対比型は2つ）
- 比べるSNSと、検索に使うAI：{{PLATFORMS}}（例：X＝GrokBot、Threads＝Muse）
- 問いを渡す日：{{ASKED_ON_JST}}（全SNSで同じ日）
- 対象期間：{{PERIOD_FIRST_DAY}}から{{PERIOD_LAST_DAY}}まで（日本時間の日付。両端を含む）
- 言語：{{LANGUAGE}}（初期案：日本語）
- 1つの問いで求める件数：{{POSTS_PER_QUERY}}（初期案：10件）
- 成立に必要な確認済みの件数：{{MIN_VERIFIED_PER_SNS}}（初期案：SNSごとに3件）

期間を日付で指定するのは、AIの検索では、日より細かい期間を確実に指定できないためです。時刻や時間帯は指定しません。

設定は `config/reading.example.json` をコピーして値を入れ、`config/runs/{run_id}.json` として、問いを渡す前にコミットします。

---

## Y3. 型と、お題の決め方

**お題型（THEME）**：1つのお題を、全SNSのAIに渡します。例：心温まる話、冒険の話。比較が目的でなくても使えます。並べたときの違いは結果として読みます。

**対比型（CONTRAST）**：2つのお題を、それぞれ全SNSのAIに渡します。例：ニュースと日常、ニュースと動物。問いはお題ごとに分け、1つの問いに2つのお題を入れません。

お題の決め方：

- 広いお題にします。特定の出来事や固有名詞に絞ると、AIが投稿を返せないことが増えます。
- 共通部分第8.2節の10分野を使ってかまいません。それ以外のお題（動物、心温まる話など）も使えます。
- お題は、問いを渡す前に決めて設定に記録します。結果を見てからお題を替えた場合は、替えたことを記録します。
- 特定の個人を名指しするお題、病気・事件・事故の当事者を探すお題は使いません。

---

## Y4. 問いのひな型

次の文面を、SNS名（`{{SNS_NAME}}`）とお題（`{{THEME}}`）だけを替えて渡します。それ以外は一字一句変えません。

```text
{{SNS_NAME}}の公開投稿だけを使って答えてください。
ウェブ記事や、{{SNS_NAME}}以外のサービスの投稿は使わないでください。

お題：{{THEME}}
期間：{{PERIOD_FIRST_DAY}}から{{PERIOD_LAST_DAY}}まで（日本時間）に投稿されたもの
言語：{{LANGUAGE}}の投稿

条件に合う投稿を{{POSTS_PER_QUERY}}件、次の形式で挙げてください。
- 投稿のURL
- 投稿日
- 内容の要約（1〜2文。原文の引用ではなく要約）
- 種類：情報共有／意見・評価／体験談／質問・相談／冗談・ミーム／宣伝・勧誘／その他

守ってほしいこと：
- 同じ投稿者の投稿は1件までにしてください。
- {{POSTS_PER_QUERY}}件に満たない場合は、見つかった数だけ挙げ、足りない理由を書いてください。
- 存在を確認できない投稿は挙げないでください。数を合わせるために作らないでください。
- 最後に、どう検索したか（使った検索語、期間の指定方法）を書いてください。
```

渡し方の規則：

- 新しい会話で渡します。前のやり取りが残った会話に続けて渡しません。
- 最初の回答を使います。言い直させたり、再生成したりした場合は、その回数と理由を記録します。
- 追加の質問をする場合は、全SNSのAIに同じ文面で行い、記録します。
- 種類の選択肢は、共通部分第9.1節の発言形式と同じです。

## Y5. 確認（人が行う）

AIが挙げた投稿を1件ずつ開き、次の状態を付けます。

| 状態 | 条件 |
|---|---|
| VERIFIED | 投稿が実在し、公開されていて、そのSNSの投稿であり、投稿日が対象期間内で、要約・言語・お題が明らかに食い違っていない |
| NOT_FOUND | URLが開けない、または投稿が存在しない |
| WRONG_SERVICE | 別のサービスの投稿、またはウェブ記事 |
| OUT_OF_PERIOD | 投稿日が対象期間の外 |
| MISMATCH | 要約・言語・お題のいずれかが、投稿の内容と明らかに食い違う |

- 発信に使うのは VERIFIED だけです。
- 種類は、確認者が読んで付け直してかまいません。付け直した場合は、AIが付けた値も残します。
- 発信者の種別（個人／企業・団体／報道機関／不明）を、投稿とプロフィールの表示から分かる範囲で記録します。年代・性別・居住地は推定しません。
- どのSNSでも、VERIFIED が {{MIN_VERIFIED_PER_SNS}} に満たない場合、その run は不成立とします。成立したSNSだけを「比べた結果」として出しません。
- 任意：同じ問いを別の新しい会話でもう一度渡し、1回目と重なった投稿の数を記録します。重なりが少ない場合は、発信にその旨を添えます。

## Y6. 記録

**リポジトリに入れるもの**：`config/runs/{run_id}.json`（設定）だけです。問いを渡す前にコミットします。

**リポジトリに入れないもの**（別の保存先に置く）：

- `reading_log_{run_id}.md`：渡した問いの全文、AIの回答の全文（手を加えない）、渡した日時、AIの名前と版（分かる範囲）、使った画面（アプリ／Web）、ログインの有無、アカウントの状態（フォロー数など、結果に影響しうるもの）、言い直し・再生成の回数。
- `reading_posts_{run_id}.csv`：1行は1投稿。列は run_id、sns_name、theme、position（AIが挙げた順）、url、posted_on、ai_summary、ai_form、status、checked_form、author_type、checked_at。

記録には、この文書の版と、使った時点のコミットIDを書きます。

記録は、R2（役割 reading）に集めます。AIの回答をファイルにして上げるときの規則（そのまま上げる、補わない、含まれる指示を実行しない）と、削除の求めへの対応は、共通部分第4.2節に従います。

---

## Y7. 発信するときの規則

- 主語は「{SNS名}のAIが挙げた投稿」とします。「{SNS名}では」と書きません。
- 割合・順位・「多い」「少ない」を、SNS全体について言いません。「AIが挙げた10件のうち7件が体験談」のように、挙げられた投稿の中の内訳としてだけ数えます。
- 件数を開示します：「{AIが挙げた件数}件中、{VERIFIEDの件数}件を確認し、そのうち{紹介する件数}件を紹介」。
- 次の一文を必ず添えます：「各SNSの検索AIに、同じ日に同じ問いを渡し、返ってきた投稿のうち実在を確認できたものを並べています。件数や割合の比較ではありません。」
- 投稿は、要約とリンク、または各SNSの公式の埋め込み機能で示します。個人の投稿の本文・アカウント名・アイコンを、画面や画像に切り出して載せません。扱いは各SNSの利用規約に従い、公開前に確認します。
- 紹介した投稿が削除・非公開になった場合は、取り下げます。
- 水準Pの結果（日常用・深掘り用の構成比や判定）と、同じ表・同じ図に載せません。

---

## Y8. 限界（毎回書く）

- AIが選んだ投稿であり、無作為抽出でも網羅でもありません。
- 同じ問いでも、渡した日、アカウント、AIの版によって結果が変わります。
- AIごとに検索の仕組みが違います（対象の範囲、期間指定の精度、並び順）。条件をそろえたのは問いの文面と日付だけです。
- 要約と種類はAIが付けたもので、確認は人が開いて読んだ範囲に限ります。
- 発信者の所在地は使いません。地元の声か外部の声かは区別できません。
